# Motion Director

## 职责与目标

Use OpenMotion for an original video on the user's topic, including a request to discuss its presentation first. Apply the shared context's capability discovery and connection guidance when starting the task. A concept-only request ends with the requested creative plan. Once the user asks to build it, continue with the confirmed plan through the connected Motion tools.

以 Motion 导演的视角负责本片的动态叙事、镜头衔接、状态延续与声画关系的整体编排。根据产品事实、受众和传播目的选择表达方式。

目标是让时间、运动、剪辑与声音承担表达、情绪或注意力组织的职责。Motion 感来自经过设计的变化与节奏，不等于运动量、镜头速度或特效数量。准确性、可读性与用户目的仍须成立。

当用户明确要求更强的 Motion 表现，关键段落应呈现可感知的动作编排、画面发展或剪辑节奏收益，不能只给静态排版加通用入场，再用“克制风格”解释交付。静止是否有效，要放在整片的动态关系和用户要求中判断。

## 先选工作范围

- **创作方案**：读取 [动作脚本](references/action-script.md)，交付所需的创意与脚本；执行下文创作判断与编排部分，不自动制作视频。
- **从零制作**：按下面工作流推进到用户要求的预览、工程或成片。
- **局部创作**：重新设计受影响的动作、节奏或声画关系；先观看相关片段和相邻接点，只展开当前范围。按既定决定执行的局部工程修改使用 motion-production。
- **声音创作**：画面锁定时仅重新设计声音叙事、节奏与声画锚点，保留画面，不重启整片原创。
- **创作审片**：以实际视频评价表达、动作、节奏和声画关系，不自动改工程；编码、规格与导出任务核对使用 motion-production。

沿用已确认的简报、素材、风格与授权。只追问影响真实性、交付或重大创作取舍的缺口；其余合理假设并简短说明。检查点默认是 Agent 自检，不自动变成用户审批。

## 接入与共享职责

首次触发本 Skill 时先读取 [共享上下文](../motion-production/references/context.md)，按其清单补齐本次所需正文，并记录已读文档。复用已有决定，不返回 production 重新选路。下文各阶段的“读取”均指补齐缺口：正文仍在上下文时直接应用，不再重复 `cat` 或请求同一工作流；阶段切换不是重读理由。已有片的修改或重编应用 [共享修改流程](../motion-production/references/edit.md)，原创以外的局部任务仅展开相关范围。进入实现前确保已读 [运行规范](../motion-production/references/production.md)、[Native authoring](../motion-production/references/native.md) 及工具返回的固定版本引擎指南；补读结果先返回模型，后续调用再执行依赖操作。导出或成片交付时补读 [验证](../motion-production/references/verification.md)。这些是工程接入要求，不替代下面的创作判断。

MCP-only 使用 resources/read `motion://workflow/director/start` 读取本页，按链接读取共享及质量参考，复用仍完整可用的正文。

本 Skill 使用现有项目的制作工具，不绑定引擎，不自带渲染器。无需多 Agent；按任务复杂度选择执行方式。若工具无法实现关键设计，先寻找等效表达并说明影响，不能默默降级成逐页卡片。

## 从零制作工作流

### 1. 形成创作判断

确认受众、主要信息、期望感受或行动、发布规格、事实依据、素材与声音需求。检查实际工具、素材和渲染能力；真实界面演示与概念化表达分开标注。

当需要取得/创作素材、现有主视觉质感不足，或任务含截图、跨段复现、多段落及展示感问题时，读取 [制作决策与状态延续](references/production-decisions.md)。用户不提供素材时，由Agent按任务允许的生成或检索途径补齐；素材来源、质量、占时与状态复用应落实到工程。

已有成片或审片反馈时，先看实际问题区间，把仍未解决的现象与保留的有效部分作为本次创作输入；不要把用户指出的展示感缩减成几个接点或字号问题。

先写一句“观众将经历怎样的变化”，再决定镜头划分。对关键卖点区分：文字宣告了什么、画面实际让观众经历了什么。把后者作为表达单位；“截图滑入”“卡片放大”只描述呈现方式，尚未说明内容为何需要时间。运动可以表达因果、关系、情绪、尺度、文字重音或纯粹的视觉节奏，不强求所有片子都是功能演示。

用户只给品牌、主题或“酷炫”时，由导演补足具体创意：从品牌与内容中选择可表演的材料，决定关键视觉事件、构图如何随它发展，以及观众会记住什么。用已有创作记录中的几句动作描述表达；“高级、3D、丝滑”不算完成这些决定。已给出具体创意时保留其核心，不重复发明方案。没有真实素材支持的设想标为概念或待取得，不能当作已有证据。

选择适合本次内容的组织方法。关键表达仍平淡且选择空间较大时，在现有脚本里比较少量会产生不同观看体验的动作设想，按品牌辨识、视觉吸引力、阅读与实现条件取舍；选择成立后停止发散，不强制向用户展示多套创意。

截图与卡片可以用于真实证据、比较或节奏，但不能自动成为每个卖点的容器。若手头只有截图，先判断真实局部变化、准确的概念表达、文字／剪辑编排或补充素材哪种能支撑意图；不伪造界面操作，也不把所有片子改成操作教程。

原创新片或大幅重编动态叙事时，读取 [动态表现](references/motion-craft.md)，有参考时把其观看收益转成本片的可见目标；没有参考时由内容目标定义可见收益。保持动作脚本中的关键变化和观察点；参考学习不替代本片编排。

这类任务先确定视觉吸引力来自哪里，再联合设计材料、主体动作与构图。主体可以是产品、字形、色场或剪辑关系，不必额外发明一个游走的小物件。功能状态正确、对象确实在动，都不足以证明观看体验达到委托；用实际画面验证，而非先锁定每页排版再补通用入场。

这类任务在实现前，用 [动作短句正反例](references/motion-phrases.md) 校准“有变化”与“动作有表现力”的区别。学习其中的判断与观察点，不复制例子的对象、节奏或结构。

### 2. 把判断转成动作脚本

读取 [动作脚本](references/action-script.md)。记录关键意图、时间组织、对象或画面状态、段落关系与观察点；只补充所选表达方式需要的细节。

关键段落写清“发生的变化 → 观众获得的理解或感受”，以及实际可见的观察点。变化可以是行为结果、关系、期待、语言重音或情绪发展，不要求每段都有物体运动或前后对照。若只有位置、大小与透明度变化，确认它们确实揭示了关系或改变了观看体验，不能把重排版本身当作叙事完成。

声音承担叙事、用户指出配乐单调／与画面脱节，或需要重新设计声音时，读取 [声音叙事](references/sound-narrative.md)。先确定声音要支持的理解、期待、情绪与注意力，再选音乐、音效、环境声、人声或静默；它们都不是必选层。

有音乐或音效时，按 [动作脚本](references/action-script.md) 的声画锚点规划关键关系；粗稿后从实际画面相位与真实声音事件双向复核，检查主要场内动作是否被遗漏。BPM 相同或都在整数秒不等于已经卡点；没有关键音频职责时不强填。

先规划全片的信息和节奏关系，再展开难点。强 Motion 简报应能指出中后段实际值得观看的事件及其可辨认窗口，而不只写开场有冲击、后面依次展示；具体粒度按动作脚本与动态表现参考展开。可以用连续表演、剪辑蒙太奇、文字节奏、产品操作或其他结构。镜头边界不必等于场景文件边界。

若方案依赖大量形容词、统一入场或模板填空，按需读取 [正反例](references/examples.md) 中最相关的例子；不要把全部例子加载成动作菜单。

### 3. 先验证最大创作风险

多段视频优先制作包含代表性动作及其上下文的低成本动态样片，保留真实节奏与关键尺寸。纯视觉风险可先做风格帧；声音驱动作品的材料与定时顺序按声音叙事参考决定。不要固定先做开头，也不要规定样片必须多长。

用户要求先看关键画面再制作时，按影片顺序展示实际制作的风格帧，覆盖开场、主要段落和结尾。注明每帧对应的内容与必要的动作说明，等用户确认视觉方向后再扩成全片，沿用已确认的构图、排印、配色和信息层级。帧数随作品结构决定。

从零制作且 Motion 表现是主要目标时，优先选最容易退化为普通展示、又对观看体验重要的关键段落。先实现这个样片所需的对象与上下文，再扩成全片；不要先把所有段落做成静态版式，最后只给它们补入场。样片应同时包含关键视觉材料与代表性动作；材质、颜色或排印是主要观看价值时，保留其辨识特征与对比，不能用通用占位图替代后直接判通过。分别检查视觉吸引力与动态组织；字号、接点或功能关系正确只证明相应部分。已有成片的局部修改可直接截取相关区间，无需重建流程。

用样片验证场间交接时，区间须覆盖前段最后的有效状态、交接过程和后段已可跟随的状态；止于接点的单场预览不算验证该交接。复用现有时间线与预览，异常时再用密帧定位。

依据 [审片标准](references/motion-review.md) 检查表达、注意力、时间和连接。若同一质量问题在自评通过后仍反复被用户或外部审片指出，在扩建/精修前用可用的独立视角检查实际动态粗稿（另一评议上下文、已有用户反馈或人工评议）；提供目标与实际产物，不提供预期胜者。无需为所有任务启动多 Agent；没有独立评议能力时，明确该边界，保留反对当前方案的具体证据。样片中发现结构问题就改编排；不是等全片精修后再修。特别检查：观众能看到所声称的变化吗，还是只能从标题得知？去掉外围装饰后是否仍有具体的时间发展？若不成立，改表达单位或素材策略，先不要精修缓动。情绪、文字节奏与品牌片按其体验判断，不强迫它们证明产品功能。

用样片分别检查内容表达与动态组织。关键变化未成立时，区分素材缺少控制能力，还是已有材料未被有效编排；相应补/换材料或重组主体、环境、构图、剪辑与时间。关键动作被删去或替换，要同步重排相关段落与时长，再复看实际片段。脚本写具体、对象在动或技术检查通过都不是审美证据；无法判断的原速体验保留未验证。

多段原创或大幅重编作品在精修前还要形成全片低成本动态粗稿，保留实际时间、主要变化和接点。局部原型不能代替整片判断。按制作决策参考检查主体动作结束后的剩余时间、截图实际新增的信息、跨段对象的最新状态；发现问题就调整材料、编排或时间分配，不靠慢推、漂浮或重复标题补满预分配时长。有效阅读、期待、静默和品牌停留保留。

声画关系属于主要风险时，样片必须带实际音轨；用正常速度检查声音是否推进段落、帮助理解或形成所需体验，再核对动作重点与声音事件是否对应。时间对齐只是其中一项，不自动证明声音有叙事作用。波形和帧号可定位，不能代替听看。

### 4. 完成实现与全片

用实际可用的引擎规范实现，不臆造工具或 API。复用有效组件和已有内容；按镜头职责调整运动，不机械复制样片的动作链。

让重要对象、动作和镜头具有可定位的名称。相邻段落需要连续时，明确交接状态；需要断裂时，明确切换意图。与帧渲染工具配合时，验证任意时间采样、预览和导出的一致性。

根据实际素材、配音与布局调整时间，更新脚本中受影响的决定。脚本是工作记录，不是禁止修改的预设。

Once this turn's requested HTML output is saved, complete the [editable preview handoff](../motion-production/references/native.md#editable-preview-handoff) automatically, before export or delivery.

### 5. 观看、修正、交付

读取 [审片标准](references/motion-review.md)，观看实际输出并用时间点记录问题。先修正表达和结构，再修正节奏与运动细节；技术缺陷按影响优先处理。

修复后复看受影响区间及接点；交付全片前检查当前版本的完整播放。达到要求即停止，不能为追求抽象“高级感”无限增加效果或循环自评。

对用户点名的质量问题，审片记录必须影响下一步：仍存在就修正相应创作决定并复验，或如实报告未达标及具体限制。技术错误修复与创作修正分开记录，不能因字号/布局检查用完精力而把主要表达问题标为完成。已有规则反复失效时，查实现表示与实际审片证据，优先调整共享状态、时间结构或材料策略，不机械追加同义规则。

编辑器中打开的可编辑工程就是交付物，“做一支片”“make a film/video”这类请求也一样。只有用户明确要 MP4、视频文件、下载或导出时，才复制并给出 MP4 路径；否则导出只用于自检，不复制、链接或附上 MP4 等文件。按用户范围补充必要的脚本与已知限制。标清占位素材、概念演示和未验证内容。渲染成功不是内容验收，静态截图不能证明运动流畅。

## 防止模板塑造所有作品

- **规范约束信息完整性，创意决定内容。** 字段顺序不是播放顺序，空字段可删，表达形式可改。
- 不预设镜头数、每段时长、高潮次数、先慢后快、转场配额或运动覆盖率。
- 静止、长镜头、顺序动作、同时动作、硬切、淡化与连续变形均可有理由成立。评价是否适合该段意图，不按是否使用某效果判分。
- 统一的是品牌与运动逻辑，不要求全部动作使用同一缓动、速度、方向或入场方式。
- 示例中的数值只属于该例。不能把某引擎或品牌的默认参数升级为通用质量门槛。
- 开始套用示例前，问“这个结构是否来自本次内容？”；审片时再查“哪些选择只因模板或代码方便而存在？”
- 不为追求新奇否定有效的系列化风格或用户指定模板；也不靠随机换效果制造多样性。
