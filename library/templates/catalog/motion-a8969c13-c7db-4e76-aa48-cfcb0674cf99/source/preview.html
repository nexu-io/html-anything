# Airtable｜用 AI 创建应用

用请求与结果并排的方式展示应用生成，再把附件更新和其他业务案例接进同一语法。

```motion-demo
{
  "id": "sequence",
  "title": "整体编排",
  "src": "demos/sequence.html",
  "duration": 58.5,
  "status": "authored",
  "description": "动作与构图示意",
  "initialTime": 22,
  "params": [
    {
      "key": "title",
      "label": "示例主文案",
      "type": "text",
      "value": "Create an app",
      "maxLength": 60
    },
    {
      "key": "accent",
      "label": "强调色",
      "type": "color",
      "value": "#ca4e25"
    }
  ],
  "presets": [
    {
      "label": "默认内容",
      "values": {
        "title": "Create an app",
        "accent": "#ca4e25"
      }
    },
    {
      "label": "OpenDesign 改编",
      "values": {
        "title": "OpenDesign",
        "accent": "#7050da"
      }
    }
  ]
}
```

## 左侧提出请求，右侧长出应用

请求发送后右侧先出现布局骨架，再填图表与字段。两侧共享同一任务名称；生成过程改变右侧内容，输入侧栏保持作为起因。

```motion-demo
{
  "id": "clip-1",
  "title": "左侧提出请求，右侧长出应用",
  "src": "demos/clip-1.html",
  "duration": 10,
  "status": "authored",
  "description": "13–23 秒 · 动作示意",
  "initialTime": 0.6
}
```

## 不同业务使用不同结果形态

地图、营销仪表盘、临床反馈表与竞品数据各有自己的布局。每个案例用一套背景色区分，浅色工作面与无衬线文字保持一致。

## 新输入要改变已有应用

附件先进入任务，再出现新增反馈字段与结果。后半成果串联只回顾已建立的能力，不在最后引入长篇新任务。

| 时间 | 段落 |
|---|---|
| 0.00–6.00s | 桌面实拍 |
| 6.00–11.00s | 地图应用 |
| 11.00–13.00s | 过渡标志 |
| 13.00–17.00s | 营销请求 |
| 17.00–22.00s | 骨架界面 |
| 22.00–25.00s | 仪表盘完成 |
| 25.00–32.00s | 新任务 |
| 32.00–39.00s | 附件输入 |
| 39.00–43.00s | 反馈表 |
| 43.00–48.00s | 竞品查询 |
| 48.00–55.00s | 成果串联 |
| 55.00–58.50s | 品牌 |

## 迁移时替换请求、数据和视图

先确定一种业务对象，再准备字段、图表或地图。输入文案必须能解释右侧产物，装载状态与完成状态使用相同位置，减少无目的跳动。
