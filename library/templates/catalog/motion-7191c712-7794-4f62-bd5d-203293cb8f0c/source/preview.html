局部动作 · 构图规则

01

先有业务问题，再连接数据

开场给少量关键指标，接一句要解决的问题，然后进入数据源连接。标题页和操作页交替出现，让复杂的数据库过程有清晰段落。

02

连接状态完成后才开始检索

数据源标记、连接动作和成功状态放在同一个局部区域。完成连接后再进入团队提问，保留数据源名称作为后续报告的上下文。

03

查询与报告互相对应

代码片段只展示影响结果的关键部分；紧接着给出对应表格或指标。保持字段名称、单位和报告标题一致，使观众能顺着问题读到结论。

画面内容制作重点
问题一个明确业务对象与时间范围
查询对应字段、筛选条件或聚合
报告承接问题的指标与结论
成果列汇总同一业务链中的交付物
04

数据多，页面仍保持留白

用浅暖底、细线和青绿强调色组织界面；大标题用衬线，代码用等宽字体，表格用无衬线。每个近景只突出一块查询或一个报告区域，长表格不缩成不可读的小图。

05

换业务时连同字段一起改

可以迁移到销售、支持或研发数据。同步替换数据源、提问、查询字段和最终数字；展示用的数据必须内部一致，不能只替换报表标题。

## 先有业务问题，再连接数据

开场给少量关键指标，接一句要解决的问题，然后进入数据源连接。标题页和操作页交替出现，让复杂的数据库过程有清晰段落。

| 时间 | 段落 |
|---|---|
| 0.00–8.00s | 数据卡与主张 |
| 8.00–13.00s | 文字过渡 |
| 13.00–20.00s | 连接数据源 |
| 20.00–25.00s | 可信数据主张 |
| 25.00–31.00s | 报告证据 |
| 31.00–38.00s | 团队问题 |
| 38.00–44.00s | 执行检索 |
| 44.00–55.00s | SQL 证据 |
| 55.00–62.00s | 成果列 |
| 62.00–71.00s | 总结品牌 |
