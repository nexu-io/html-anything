# OpenMotion：All-in-One AI-native Studio 产品蓝图

更新：2026-11-08。本文维护已确认产品方向、概念与后续验收方式；当前实现以 [产品架构](architecture.md)、[Model Gateway](../model-gateway.md) 和 [工程契约](../project-workspace.md) 为准。本文不代表新增能力已经上线。

## 用户问题、对象与预期结果

个人创作者、讲师和小团队需要把找灵感、收集素材、生成媒体、讲故事、剪辑改稿和交付连接起来，并在后续创作中沿用品牌、偏好与有效方法。面向团队，还需要把评论、评审、任务和共同知识保留在作品上下文里。媒体及其 Agent 则需要能够复述完整产品，而不混淆当前实现与长期愿景。

这些方向来自本次明确产品需求；没有新增访谈、市场规模、采用率或付费意愿证据。预期结果是：用户理解一个完整的创作空间，知道今天可以从哪里开始，并能识别哪些环节仍在建设。

## 三层产品定义

| 层次 | 对外表达 | 对应含义 |
| --- | --- | --- |
| 产品形态 | **All-in-One AI-native Studio** | 一站式视频创作与剪辑空间，连接发现、素材、叙事、制作、协作、交付与后续学习 |
| 核心体验 | **AI-native、开源 CapCut 替代** | 人与 Agent 围绕可编辑时间轴组织故事、落实剪辑和反复调优；Claude Motion 为动效创作参照 |
| Agent 概念 | **Super Motion Video Agent** | 理解个人/团队上下文，组织长期创作任务，协调工具和多模态模型，处理评审并复用经验的目标体验 |

使命仍是 **Edit with AI. Everyone can be a creator. / 人人都是 AI 剪辑师，人人都是自媒体。** All-in-One 描述完整产品范围，不能据此把路线图能力写成现有功能。Super Motion Video Agent 是本项目提出的产品概念，不主张未经研究证明的行业首创或世界第一。

## 创作与运营生命周期

| 环节 | 期望体验 | 当前已实现基础 | 已确认方向 / is coming |
| --- | --- | --- | --- |
| 发现 | 找灵感、参考、模板与可用材料 | 模板/参考目录、搜索、预览与原始来源 | 跨素材服务搜索、个性化发现与灵感集合 |
| 收集 | 上传、整理、复用素材并记录出处 | 工程媒体导入、预览、添加、重命名等文件操作 | 跨项目和团队的共享素材库与协作管理 |
| 生成 | 调用合适的图片、视频、配音与音乐模型 | Studio Model Gateway、配置与模型发现、任务状态、候选素材入库 | 搜索、采购/选用和生成的统一创作任务编排；Avatar 服务发现 |
| 叙事与剪辑 | 按个人口吻组织故事，在时间轴安排画面、动作与声音 | 外部 Agent 基于脚本/时间码编辑；人工时间轴调整；图片生成候选与显式替换 | 自动内容选择、语义剪辑和目标平台自动适配 |
| 协作与评审 | 人和 Agent 共同编辑，在时刻/范围上讨论和评审 | 同一本地工程的交接、版本与 revision 保护 | 时间轴评论、共同评审、团队空间及协作状态 |
| 交付与运营 | 导出、管理发布计划、制作任务与周期性内容 | 固定版本 MP4 与可编辑源工程；生成/导出作业状态 | 多平台发布管理、创作任务管理、定时与事件触发自动化 |
| 回收与改进 | 结合表现数据、反馈与上下文改进下一次创作 | 手动评审、显式提供品牌与动效文档、手动维护 Skills | 平台效果数据回收、版本关联、个人/团队记忆、RAG 与 Skill 改进流程 |

```text
发现灵感 → 收集素材 → 规划故事 → 生成与剪辑 → 协作评审 → 导出
                                                       ↓
               以下为规划：发布与任务自动化 → 数据回收
                                                       ↓
下一次创作 ← 检索合适知识与 Skills ← 评估并沉淀方法、偏好和品牌
```

Input → Process → Output 仍是当前制作链路；发布、反馈与知识复用将它扩展成跨作品的循环。生成/导出作业管理不同于创作任务系统，版本历史不同于长期记忆，模型目录也不同于素材或 Avatar 搜索服务。

## Super Motion Video Agent

我们提出的 Super Motion Video Agent 以完整作品和长期创作任务为对象。它的职责是理解目标与品牌、安排执行、调用合适的工具和模型、检查作品，并在后续任务中使用经过确认的知识。

### 五类职责

1. **理解创作者。** 读取受众、口吻、品牌、团队背景、参考与既有偏好，形成可检查的创作简报。
2. **组织任务。** 将目标分解为调研、素材、脚本、剪辑、评审和交付，保留任务进度、依赖、输入、输出与失败原因。
3. **协调执行。** 使用 Skills、模板、素材服务与多模态模型；候选媒体与最终采用区分，修改落到同一份工程。
4. **持续协作。** 接收时间轴反馈，保留修改范围与保持项，继续迭代并交付可复查的版本。
5. **复用经验。** 根据创作评审与版本关联的数据提出方法改进，将可验证的方法整理为 Skill、模板或偏好更新。

当前由外部 Agent 客户端承担需求理解与工具编排，Studio 不内置常驻 Agent。上述跨任务协调、事件调度、长期记忆和数据反馈属于目标设计；不新增第六个核心 Skill，也不改变一期十一个公开 MCP Tool。

### 参考与区别

参考 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的插件化扩展思路，以及 [dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype) 对事件与持续任务的探索。核查日期为 2026-11-08。后者 README 将其标为研究原型，并明确与内部版本和文章中的设计存在差异。

OpenMotion 将持续任务理念用于视频创作场景；本次只更新产品文档，不引入其代码、运行时或已实现能力。名称是本项目的概念定义，不代表 DeepSeek 背书。

  创作上下文        执行能力              长期任务
  [已有] Skills     [已有] MCP / CLI       [规划] 定时 / 事件
  [已有] Brandkit   [已有] Model Gateway   [规划] 发布管理
  [已有] Motion MD  [规划] 搜索连接器      [规划] 效果回收

## 知识、RAG 与数据闭环

目标是让每次创作留下可用的知识，而不只是一次对话。

| 知识或数据 | 沉淀什么 | 下一次如何使用 |
| --- | --- | --- |
| 个人与团队偏好 | 口吻、节奏、排版、常用工作方式及确认过的取舍 | 为新简报提供适用偏好，区分个人、团队与单项目范围 |
| Brandkit 与 Motion MD | 品牌事实、素材、视觉与动效规则 | 为 Agent 提供表达约束与可参考的设计体系 |
| 项目与评审 | 具体版本、修改原因、被采用与被否决的方案 | 回答某个选择为何成立，避免把单次意见当永久偏好 |
| 模板与 Skill | 可编辑结构、参数、方法、示例与验证结果 | 按任务检索并复用，也能替换品牌、叙事和内容 |
| 发布与表现数据 | 发布目标、作品版本、时间窗及平台提供的表现指标 | 比较具体版本和内容假设，为后续创作提出可检验的改进 |

**规划中的循环：** 收集相关数据 → 关联工程/成片版本 → 提取有来源的知识 → 通过 RAG 检索适用上下文 → 提出 Skill、模板或偏好更新 → 评估后保存 → 用于下一次创作。

RAG 指按需检索已有知识，不等同于训练模型。Skill 沉淀先形成可审阅的候选与验证记录，不把每次生成或曝光变化直接写成有效经验。不同平台、发布时段和受众的表现不天然可比；是否持续改进仍是需要验证的产品假设。

当前没有发布数据连接器、向量检索服务、自动偏好记忆或自动 Skill 学习。个人/团队知识范围、来源、修订与移除方式将随相应能力设计；本次不收集用户数据或修改宿主记忆。

## 技术原理与可验证契约

### 当前：从剪辑意图到固定版本成片

```text
01  创作者 → Agent
    提供目标、素材、脚本 / 时间码与保持项

02  Agent → openmotion_get_project
    读取 projectId 对应的源码、上下文、revision 与 versionId

03  Agent → openmotion_edit_project
    提交 files + requestId + expectedRevision + expectedVersionId
    ├─ 版本冲突：拒绝过时写入 → 重新读取 → 协调修改
    └─ 写入成功：保留新版本 → 通知编辑器文件监听

04  Agent → openmotion_open_preview → Studio
    人工检查预览、继续细调；需要修改时回到步骤 02

05  Agent → openmotion_export_request
    指定 projectId / revision / versionId → 固定工程与本地素材快照

06  渲染服务 → MP4 + 技术检查
    lint → render → 规格检查 → 完整解码 → 代表时间点 seek

07  Agent → openmotion_get_project（exportJobId）
    等待实际产物 → 返回文件 → 正常速度审听 / 用户验收
```

图为现有契约的职责概括，具体参数与任务查询以 [MCP 契约](../mcp-phase1-tools.md) 为准；人工审片与发布不因渲染完成自动发生。

### 规划：把表现数据转成可用知识

```text
EVIDENCE · 建立证据
  评审意见 / 平台表现 / 素材来源
    → 关联项目 + 成片版本 + 平台 + 时间窗
    → 保留出处与适用范围

RETRIEVAL · 为下一次创作找上下文
  新简报 + 个人 / 团队范围
    → 检索相关知识
    → 组合品牌、偏好、方法与示例，并保留来源
    → 执行创作，保存可编辑结果

IMPROVEMENT · 评估后复用
  任务目标 + 实际结果 + 反馈
    → 评估差异
    → 形成 Skill / 模板 / 偏好更新候选
    → 审阅并保存版本
    → 回到知识库，服务后续检索
```

这段流程全部描述未来知识能力。索引结构、检索方法、任务调度和评估服务仍待实现方案确认；不预先宣称采用某个向量数据库、自动训练或具体模型架构。

| 技术机制 | 解决什么问题 | 验证重点 |
| --- | --- | --- |
| revision 与明确工程身份（已有） | Agent 与人工编辑交接时避免过时写入、跨工程误改 | 冲突识别、重新读取、目标工程归属 |
| 候选素材与采用分离（已有） | 生成结果不等于用户决定采用 | 文件可用、采用目标、时段与撤销行为 |
| 固定快照导出（已有） | 修改中的项目与最终文件可能对应不同版本 | 工程、revision、实际输出与技术检查对应 |
| 持久任务与事件触发（规划） | 长期制作、重复任务和执行中断需要连续状态 | 状态恢复、重复事件、依赖与失败记录 |
| 带来源和范围的检索（规划） | 品牌、偏好与历史反馈不能无差别混入每次任务 | 来源、个人/团队/项目范围、检索相关性 |
| 评估后沉淀 Skill（规划） | 一次偶然结果不足以证明方法有效 | 对照任务、候选差异、验证记录与版本回退 |

## 为 Agent 打造的模板社区

社区资源应同时服务人和 Agent：提供预览让人判断效果，提供源码、可修改项、Motion MD、素材来源和制作说明让 Agent 继续制作。初始入口仍为 [Library](../../library/README.zh-CN.md) 与三个内置模板。

当前的“一键复刻”准备参考与指令交接；制作由连接的 Agent 按模板或复刻路线完成。可编辑模板复用与外部参考重建分开。目标体验进一步覆盖自动发现、安装、品牌化替换、个性化调优与方法回流；不把目录中的外部参考全部计为可执行模板。

## 验收与后续验证

- **本次文档交付：** 双语首屏可复述 Studio、时间轴和 Agent 的三层关系；完整环节、状态、参考与使用入口一致；本地链接、Markdown、文本架构路径、分发清单和版本锁检查通过。
- **后续能力交付：** 分别验证搜索素材可用、生成结果可采用、剪辑修改可继续编辑、任务可以恢复、发布记录可追溯、反馈能关联正确版本、知识检索有出处；每项以实际实现和测试为准。
- **产品假设：** 理解个人/团队能否减少重复说明，协作能否减少改稿往返，数据与 Skill 循环能否提升下一次作品。需要创作者使用证据与内容验收，不能由技术检查推定。

本轮不改变账户、价格、收费能力、应用行为或工具契约，也未确定发布日期。
