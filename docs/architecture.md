# Product and lifecycle architecture

## Product purpose and current user flow

OpenMotion combines editable native motion projects, human editing and Agent access. The primary reference product lives on `main`; this independent refactor line implements a subset through shared product contracts. The visible Web MVP creates or opens a project directly. Existing session/artifact/message APIs retain real instructions and caller-supplied messages. Users and Agents edit native source or supported fields, preview a confirmed revision and use persistent undo/redo. Web, HTTP and Codex MCP consume the same domain transactions. Fixed-revision background film export is available through Web, HTTP and MCP on the qualified native platform. Three finite built-in templates can create independent editable projects through the same Web/HTTP/MCP contract. Explicitly configured Prism publications support bounded discovery and verified text-source creation; binary template resources, production model adapters, host reference acquisition/comparison, complete portable-template qualification and broader media editing remain separate implementation and acceptance work. An injected PNG provider can drive durable material tasks and explicit candidate adoption; the local protocol fixture does not qualify actual model execution. Complete versioned creative guidance is available for the five intent routes, while its methods explicitly distinguish supported product operations from required host capabilities. An engineering reference or returned URL is not evidence of a completed production workflow.

The complete product's template environment, eleven interface languages and host editable-preview handoff must be absorbed through their actual domain owners. They must not introduce a second project store, host-resource inventory or source-of-truth timeline. Product creation and user visual acceptance remain distinct from a successful mechanism/build test.

## Product reference and acceptance boundary

`main` owns the current reference product; `refactor/odsuite` remains the independent implementation and integration line. The owning work item records each exact reference SHA, capability matrix and active delivery order. At slice boundaries, review main additions and deliberately update that record. A moving reference does not invalidate an accepted slice or silently expand its original claim.

Read actual route composition, visibility gates and the published MCP/HTTP profile before assigning coverage. Separate visible MVP behavior, supported public contracts, retained backend/hidden functions, proposals and explicitly excluded scope. The reference MVP hides several advanced editing/generation and conversation/browser entry points; their source presence does not require restoring those panels. Retain accepted refactor domain contracts, data and lifecycle guarantees while reorganizing product presentation. Absorb user outcomes through the four owners below rather than reproducing legacy routes, filesystem authority, queues or compatibility APIs.

Historical feature snapshots and unmerged PRs support investigation, not shipped-coverage claims. Browser fixtures keep their actual original source/viewport/font/interaction provenance until a new reference is captured and checked. Existing mechanism evidence, current visible parity, installed host behavior, native/platform execution and publication are distinct acceptance dimensions. Optional Library resources and format proposals do not imply a new parser, marketplace or resource permission. Telemetry and additional delivery carriers remain outside the agreed composition.

The product delivery targets are standalone and Codex Plugin. Electron/Capsule and Docker are not product carriers.

## Identity and system resources

Release owns product/channel/version. Sidecar owns resource factories keyed by `<channel, namespace>`. Channel is a product distribution lifecycle: `X.Y.Z` or `X.Y.Z-<channel>.N`; namespace isolates independent resource domains within a channel without creating another product version. All deliverable carriers share one version and release together; pack/pipeline separate actual carrier assembly capabilities internally.

`odsuite.yaml` defines product defaults. `protocolIdentity` computes local communication and OS application schemes; never infer channel from an arbitrary URL, port or data directory. Environment facts, release identity and OS resources must not create parallel authorities.

Processes obtain identity, ports, paths and lifecycle through sidecar. The directory records committed facts; OS observation proves liveness. Public APIs hide arg stamps, private startup protocols, stop escalation and retirement. Independent managers and managed workloads have separate identities; launcher ancestry does not authorize cross-domain takeover. Callers negotiate business communication. Inspect neither owns another inventory nor fixes business/debug protocols.

## Delivery lifecycle ownership

The current product composes only standalone and Codex Plugin. Feature-branch implementations provide lifecycle behavior to absorb, not a script/configuration blueprint. Both carriers share a product/channel/version; carrier identity does not add a new resource factory dimension.

| Lifecycle                            | Owner and boundary                                                                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Version and identity                 | Release validates product/channel/version; pipeline selects one version for both carriers.                                                             |
| Closure and local artifacts          | Carriers choose finite entries/resources; pack compiles portable Node24 closures, retains dependency notices and produces verified immutable archives. |
| Runtime start/stop/recovery          | Carriers compose services; sidecar owns process identity, grants, liveness, drain and explicit interrupted-owner recovery.                             |
| Native preparation and GC            | Render explicitly prepares its pinned tools through Blob verification/materialization and actual renderer Uses; Blob owns cache retention and GC.      |
| Immutable installation and selection | Installer journals exact source/data intent, verifies immutable Node closures and commits durable receipts/selections; it owns no product runtime.     |
| Product setup and host registration  | Application composes both carrier installations; Codex projects owned MCP/Skills through an injected installer Context and managed CLI child.          |

Pipeline stages both actual built closures under one fingerprint. Channel selection changes identity, not quality policy. Independent policy/tests/artifact gates are available; archive checks do not establish installation or host loading. The old Electron-specific pack/release/desktop gates are removed rather than retained as aliases. Pipeline also emits one finite npm kit with the shared version, positive tool files, payload manifest and both verified carrier archives. Loading it binds npm metadata, complete inventory and payload bytes to the fingerprinted source closures; a self-consistent hash receipt alone is insufficient. Publication is not connected.

Standalone and Codex have independent bundled entries, Web, Daemon and render worker, with no Electron or workspace dependency. Installer now owns Node installation under a sidecar authority separate from runtime data: a product policy, immutable per-carrier/version/digest closures, SQLite intents/receipts and current selections. It verifies complete bounded archives and files, rejects conflicting same-version content and unowned targets, and never initializes runtime user data. Replay returns its original receipt without rewinding a later selection. Interrupted authority requires explicit sidecar recovery before replay. Missing/truncated established journals fail closed. Generic runtime/distribution still retain disconnected shell-oriented activation contracts; they do not qualify Node automatic updates.

`packages/application` is product installation/control composition, not another carrier or resource authority. Its only public bin is `odsuite`, invoked through the local npm kit. Setup verifies both payload identities before writes, installs both at the shared version and optionally injects the installer factory/Context into Codex registration. Request identity depends on the fixed product/scope/data/source intent, never an npx cache path. Persistent registration points directly to Node and the installed Codex closure; transient registration workers finish before installer drain. No install hook or global bin is used.

Application-kit candidate discovery uses distribution's signed heads and shared durable catalog selection, under `products/<product>/kits/channels/<channel>/head.json` and immutable `kits/releases/v<version>/metadata.json`. Signed metadata binds the bounded npm artifact, product/channel/version/revision, source commit and build fingerprint. The pipeline derives it from verified build/package receipts. The client pins the public key, rejects regressed/conflicting revisions, version regression and same-version replacement, and fails on unavailable sources without presenting cached metadata as fresh discovery.

Installed `odsuite update check|prepare|discard` runs through an `updates` hosted Context in the existing installer factory. It first verifies both selected installed carriers against the invoking kit. Distribution handles identity and transport; application checks the complete finite npm inventory, product manifest, canonical installer source validation and both actual closure identities before preparing. A real Blob Use protects download/verification; only a fully checked candidate replaces the prepared reference. Failure preserves the previous prepared candidate. Discard releases that reference under normal Blob retention; it preserves discovery history, installer selections, registration, live runtime and user data. Preparation executes no downloaded code and performs no activation. Candidate signing/publication and automatic discovery/activation remain separate lifecycles.

Explicit activation is an installer-owned, resumable sequence. Its separate sidecar-granted transition journal retains immutable request intent, progress, optimistic revisions and completion history without owning process liveness. Installer stages immutable carriers without selecting them, then atomically compares and swaps the complete selection set at one shared version. Existing setup/selection commands are fenced while an activation remains unfinished. Application stores per-artifact signed preparation receipts before switching Blob protection, so a later failed candidate does not erase the prior prepared identity.

`update activate` pins the caller, signed candidate, old receipts, original runtime witness and owned registration destinations before effects. It stages both closures, verifies the current owned Codex configuration/Skills, stops only the same stamped standalone Manager, commits both selections, reconciles owned registration and restores a running target only if the original runtime was running. Cleanly stopped roots stay stopped. Self-hosted Codex must detach first; existing stdio transports are not transparently migrated. Fresh host connections use the updated installed Codex path and share the target runtime through existing admission.

This sequence is not a global atomic transaction across runtime, host configuration and storage. Failure preserves its actual committed phase, cache recovery protection and diagnostics. An exact request retry resumes after explicit sidecar recovery when authority was interrupted; a changed owner/configuration refuses destructive progress. The registrar may reconcile only the exact pending target version during the registration phase. Completed intent replay returns its original receipt without rewinding later selections or restarting a later runtime. Intent status is separate from actual runtime health. Prepared/recovery references are released after completion; installer/registration history and user projects are outside cache GC.

Registration journals the exact selected profile and supported `.agents/skills` projection before host mutation, checks ownership/file hashes, and reconciles unknown CLI outcomes against that same intent. It grants selected paths before creation, does not invent Skills scan settings and never overwrites unrelated files/transports. `CODEX_HOME` selects a Codex profile; Skills discovery remains host/workspace based. Setup is not an atomic all-carrier activation: a failed later step retains its earlier committed receipts for explicit same-intent retry.

Installed-code consumption is distinct from Blob cache Uses. Installer journal format 3 records immutable selected-receipt/process-witness bindings and retains them across controller shutdown and explicit recovery. Sidecar captures the local installation controller or revalidates the exact launched runtime Manager and observes PID/birth liveness; installer stores references, never cached liveness or a second process inventory. Closing an installation/runtime root does not prove a stdio process exited. There is no early release operation: only actual process retirement makes the observation retired. Observation failure preserves uncertainty by failing the read.

Application holds installation authority across standalone/preparation launch and consumption commit; a failed commit drains only that exact new Manager or retains uncertain diagnostics. Activation uses its existing installer session, avoiding a nested owner. Managed Codex registration carries explicit installation home/base-product/request binding (the base product is not the channel-derived application ID). Bootstrap verifies the selected immutable receipt and its path/data/carrier before connection or self-hosting; stale selection fails before starting product resources. Raw unpacked carrier composition remains caller-owned and does not grant permission to collect installer directories. Installed journal formats are strict: formats 1 and 2 are rejected without migration/reset. These are entry-process consumption facts, not whole-tree retirement proof: runtime factories, stamped descendants and interrupted authority still require sidecar drain/recovery. Explicit installed-kit `gc plan|apply|status` now closes quiescent code retirement. Application verifies owned host registrations and passes their installed receipt references; installer protects current selections, all unselected preparation and incomplete installs, and sidecar-observed live consumers. A runtime root must be absent or fully closed with retired factories/instances and no observed stamped process trees; live or uncertain authority refuses collection. Installation authority remains held through eligibility and deletion, serializing managed startup and registration against collection. Raw composition is outside this contract.

Plans bind the exact inventory, protection and runtime facts to a fingerprint; changed plans refuse before retirement. Installer journals all target paths as retiring before deleting any bytes, fences conflicting install/stage/select/use/update/start, and deletes only verified manifest files/directories. Unknown entries, links or changed remaining bytes preserve the interrupted record. Exact retries resume after explicit sidecar recovery when interrupted; completed retries return their original result without affecting later selections. Retired versions cannot be installed, selected or consumed again, including via new request IDs. Version manifests, original receipts, activation/registration history and collection records survive removal. Collection does not traverse npx caches, staging attempts, user projects/media/exports or Blob cache; it has no background scheduler or automatic rollback.

## Blob and persistent user data

Blob owns digest verification, typed materialization, CAS/cache, references, actual Uses, retention and GC, using sidecar-granted paths. Prepared/current/recovery references protect candidates and recovery; real processes, documents, streams and readers hold Uses until drain. Small file/content-directory resources retain their 64 MiB bound. Native ZIP resources stream into CAS with a trusted compressed digest/size (at most 512 MiB), plus an independently declared materialized-tree digest and expanded byte count (at most 2 GiB / 8192 entries). ZIP inspection rejects links, special files, traversal, duplicate/case-colliding names and undeclared expansion. Native consumers receive verified paths rather than buffered archive reads. Unknown or failed consumers stay protected rather than being declared dead by elapsed time.

Projects, sessions and export outputs are persistent product data and never content-GC input. Stopping a process or removing a reference does not delete transactions, installation policy/history or user content. GC requires proof of no references, no actual consumers and satisfied retention.

Compose atomic operations in the same factory/session: same-factory reentry is supported, cross-factory operations rejected and scoped handles expire after callbacks. Background controllers separate initialization scheduling from stop lanes; quiesce drains them before stopping. Do not wait for a competing background lane while holding one.

## Standalone and Codex composition

Standalone directly composes sidecar manager/factory, serve source and an independent Daemon process. It does not create Electron/Capsule actors or reuse Electron content generations as its product state. Serve sources can join an existing factory and do not own update policy.

Web reads the Daemon endpoint/capability and environment from same-origin in-memory `bootstrap.json`, or an explicitly supplied host preload. Never persist the capability into source/static content. Separate static roots from managed resource roots. Daemon listens only on a granted socket and sidecar forwards its port; persistent data is a hosted Context grant. Temporary ports/sockets retire with lifecycle.

Before workspace mount, Web presents a loading state and bounds the bootstrap request to ten seconds. A failed fetch, invalid configuration or deadline produces a sanitized, explicit retry action; it never displays capability/transport diagnostics, changes the original project entry or creates a project. Only one attempt runs, and startup disposal aborts/drains it before removing the view. After mount, serial read-only workspace observation owns connection feedback and manual retry. Normal polls do not repeat live announcements. Unconfirmed writes and product operations fence observation; reconnect preserves mounted inputs, drafts and original receipt identities rather than remounting or replaying writes. These are business-connection facts, not OS liveness. A replaced runtime may have new grants/capabilities: the operator obtains its current entry through existing status controls. Web neither scans ports nor restarts/takes over instances. Native preparation remains the renderer-owned explicit operator lifecycle described below; this startup state does not claim that vendor tools are ready.

Shutdown stops new work and drains producers and caller-tracked requests outside the factory stop lane before process release. In-process Daemon hosts run HTTP quiesce outside that lane: accepted handlers and their response finish/close events drain before unused connections close; store retirement follows in stop. Standalone first quiesces its Prism producer and tracked requests, then releases the real Daemon and only then retires capabilities. Failed drain preserves authority and diagnostics. Startup rejects a live root; interrupted authority requires explicit recovery rather than deleting ledgers or writing carrier PID files.

Codex owns its descriptor, stdio transport and environment collection; it reuses standalone Web/Daemon and sidecar. The official MCP SDK owns protocol transport/discovery. `runtime_status` reports actual environment, health, URL and release identity. Product tools are registered by `apps/daemon/mcp` using its combined workspace/export/template contract; carriers do not copy domain logic. Unknown tools reject explicitly. `project_entry` validates explicit session/artifact, content revision and history version without changing selection. The MCP adapter binds that target to the actual managed Web origin and a bounded fragment; it reports display as unverified and neither opens a browser nor queues a host panel. HTTP returns the same target without inventing a host origin. Web cold entry and subsequent fragment navigation check the exact target and the observed current-selection preconditions in one `artifact_enter` workspace transaction. A same-content historical return still needs its current history version. Lost responses retry the original request; replay never rewinds later selection. Ownership, stale content/history or selection changes fail explicitly, without substituting a global most-recent project. Hydration validates the target again before publishing editable content. Local drafts reject a new entry until explicitly resolved; fragment changes wait for the accepted operation and its unknown receipt to settle rather than replacing that intent. Successful explicit Web operations acknowledge the held project revision/history in the address using replaceState, so a GUI-created/edited project can reload at its confirmed version. Initial resume and hash admission preserve caller intent; background observation never silently rewrites a bound address. A stale externally bound URL needs a fresh entry; a plain Web address retains the ordinary workspace-resume behavior. This establishes entry validation, not host queue/display/review observation. A URL does not mean a host panel opened. Live admission selects the ready hosted composition through sidecar and reads its immutable release manifest and carrier identity before probing Daemon health or requesting delegation. The current policy compares complete release manifests. A mismatch reports `runtime_release_mismatch` with the requested and running manifests plus the observed sidecar owner. This admission point owns future protocol and capability negotiation. Cold startup validates persistent formats separately. Its EOF closes only the transport; absent/cleanly closed authority may self-host and then EOF drains that owned runtime. Live-unready, mismatched, incomplete and interrupted roots reject without takeover; startup EOF must also drain.

The Codex build contains one manifest, MCP descriptor, bundled stdio/server, Web, independent Daemon, render worker and five finite local Skills with their referenced guidance. It can run without workspace/node_modules, with the shared product version. This is a Node24 closure, not proof of installation, signing, platform packaging, model generation or creative acceptance. Native vendor tools are verified resources, not bundled system executables. OS temporary socket bases are short, isolated by UID/root/factory/resource and recorded by sidecar; consumers never derive another authority from their own TMPDIR.

Installed product controls are composed by `packages/application`, not another process authority. Status returns the sidecar-derived runtime root. Restart first admits the running release, verifies the installed standalone receipt and rejects pending installation transitions/GC under installation authority. It stops only the exact observed stamped Manager, launches the selected closure and records its actual Use before releasing installation authority. Failed stop prevents launch; failed launch does not silently roll back selections or remove data. Transport clients reconnect after replacement. Self-hosted Codex stdio closes through its connection owner instead of operator takeover. Development watches and installed immutable-kit operation have separate entries into the same sidecar mechanisms.

## PNG generation tasks and explicit adoption

`packages/gateway` owns durable fixed-intent PNG tasks and immutable, project-bound candidates. Carriers inject an explicit Provider identity/version/model set; no environment credential fallback, model auto-selection, production network adapter or paid execution is implied. Standalone always hosts the journal so tasks and candidates remain readable after restart without an adapter. Task pages respect both maximum entry count and the control wire byte budget.

A task records its initiating session/artifact/revision, model and prompt before submit. The attempted marker precedes the external call; unknown submission never resubmits automatically. Queued work may be cancelled before invocation. Producer callbacks, persistence and blob cleanup drain during quiesce outside factory stop lanes.

Candidate success changes no workspace source, history or selection.

Adoption explicitly selects the job, candidate content hash, project ownership, expected revision, resource path and name. Lost responses replay the same intent even after later edits or remote unavailability. A stale new intent rejects without overwriting a newer project. Adoption does not insert or replace native elements: that remains the existing explicit media insertion/editing flow.

## Native-content archive contract

`packages/portable` owns a pure native-content ZIP codec, separate from suite pack’s Node code closures. `prepare` verifies one complete workspace source/media payload and returns an immutable byte identity, length and repeatable chunks of at most 64 KiB. `read` consumes bounded bytes against the caller’s fixed archive digest, verifies the exact inventory and returns a complete source payload for workspace’s existing atomic source-intent transaction. It allocates no path, listener, process, timer, project journal or current pointer. Transport cancellation/deadlines, actual reader drain and staging/output paths belong to the caller under sidecar ownership; Daemon composes public HTTP/MCP/Web business transfer as described below.

ZIP source and PNG/WAV/font resources remain ordinary root-relative native files with unchanged bytes, including native configuration, permitted Studio manifests and supplied notices. The sole reserved `.openmotion/manifest.json` is a canonical schema1 inventory: source path/size/digest and verified media names/facts. It is engineering transfer metadata, not a video content schema or runtime authority. It contains no product channel, namespace, project ID or OS path. The archive digest binds container bytes; workspace independently derives the project revision and creates new ownership IDs. Canonical project-content identity remains workspace’s responsibility.

Bounds reuse workspace’s 128 text files / 4 MiB, 64 media / 64 MiB and 16 MiB per media entry. The inventory is at most 256 KiB; the complete container is at most 72 MiB and 193 entries. Encoding emits deterministic classic ZIP regular0644 files with fixed dates and stored content. Decoding also accepts bounded classic DEFLATE entries and verifies local/central agreement, contiguous coverage, expansion, CRC, canonical inventory, every content hash and decoded media facts. Encryption, descriptors, ZIP64, comments/extras, directory/special entries, unlisted files and duplicate/case-fold/file-directory collisions reject. Portable paths require NFC and reject host-reserved names and Agent instructions; unsupported names are never rewritten.

Native integrity is separate from dependency closure, rendering, font redistribution rights or a finished reusable-template package with matching film/cover. This codec preserves supplied source/licensing bytes and performs no engine injection, external retrieval, preview generation or publication. Daemon owns the bounded in-memory transfer and public import composition described below. Complete relocated/offline/native acceptance remains separate from byte integrity and independent creation. Persistent delivered user packages and imported workspace bytes are outside Blob GC.

## Native editing and previews

The graph resolves references relative to the declaring file inside the confirmed text snapshot and distinguishes reusable file definitions from mounted instances. Instance IDs follow SDK host-chain scopes; each instance maps to its source file, declaring host and parent. Runtime composition IDs are assigned with the pinned native compiler so repeated files, local element IDs, scoped CSS/scripts and SVG references remain isolated. Authored timing expressions are retained, not guessed into a second timeline model.

Preview opening validates and assembles the whole reachable graph before registering a candidate. The canonical pure inliner consumes snapshot files and verified immutable media facts; it has no host filesystem/network resolver and creates no physical shadow project. Compiled HTML, engine tags and instance markers remain ephemeral. Missing/unusable references, cycles, ambiguous identity, escaping references and bounded expansion failures reject the candidate; the last confirmed Web frame remains visible. The graph is capped at 128 files / 4 MiB, 256 mounted instances and 20 nested file edges, with 16 MiB of expanded source and 32 MiB of assembled HTML. Composition previews require explicit external-file boundaries; ambiguous embedded compositions are rejected. Only the entry document is a runtime preview; other snapshot files are read-only resources. Nested canvas messages carry scoped identities. Only elements belonging to the active editing instance may move; other instances and composition boundaries remain protected.

Native previews support repeated file mounts, template grandchildren, GSAP execution at distinct local times, relative SVG/CSS/JS resources, failed-candidate retention, undo, browser reload and cold carrier restoration. Motion defines the editing context from the confirmed or explicitly drafted source snapshot. Web owns the ephemeral composition stack and per-level playhead restoration. Each context identifies one mounted instance and its owning file; changing shared source updates every instance of that file through the existing workspace revision/history transaction. Navigation flushes and confirms the current draft before switching. Transform results must still match the artifact, revision, instance, file and complete source projection that produced them. Failed saves retain the current context/draft; removed instances explicitly invalidate to the root rather than selecting another mount of the same file. Browser reload starts at the root while committed files and history survive carrier restart. The canvas remains the actual global composition. Local controls map numeric one-to-one ancestor starts into global playback time and respect the intersection of instance windows. Unresolved timing expressions or unusable windows expose a read-only editing context rather than a guessed clock; direct source editing remains available. PNG images and PCM16 WAV resources use the separately bounded workspace manifest described below. Arbitrary remote dependencies, additional codecs and render/export remain outside this preview contract.

Source-derived artifact creation accepts one resolved payload of finite text files and verified PNG/WAV/font bytes. Workspace stores the complete initial resource manifest, revision, history entry and immutable-source receipt in one transaction. A failure, including receipt persistence, rolls back every project and resource write. Replay confirms the original receipt before resolving bytes, preserving later edits and selection. Composers verify external source identity; workspace verifies native paths, media formats, aggregate bounds and source/resource path collisions. Current template adapters explicitly supply an empty media set. Daemon composes native-content archive import through the same transaction; supported media formats remain unchanged.

User-imported media belongs to workspace persistent data. The current database format is 3; discarded formats are rejected without migration or reset. A revision hashes canonical text files plus a sorted resource manifest (logical path, display name, verified digest/size and format facts). Verified bytes are deduplicated in the same SQLite database and are readable only through an explicitly owned immutable revision. Imports/removals, current pointers, history and idempotency receipts share one transaction. Source saves preserve the resource manifest. Removing a resource changes current membership; historical snapshots and existing views retain bytes. No user-media GC, blob-cache ownership or physical source copy is introduced.

Single-face TTF/OTF/WOFF/WOFF2 fonts are persistent project resources under those same limits and transactions. Workspace derives family/PostScript name, slant and weight range from exact bytes through pinned fontkit 2.0.4; container/table/name/variation bounds precede lazy metadata decoding, with a 32 MiB decompression ceiling. Collections and system-font discovery are outside this contract. The content digest derives one reserved OpenMotionFont_<digest> family identity, avoiding collisions between same-named uploads. Motion consumes the workspace identity contract and injects font-face rules only into derived preview/render HTML; those rules and host font paths are never persisted into authored source or Web styles. Static owned-family references in native styles, inline declarations and project CSS require matching manifest bytes. Missing resources reject a candidate rather than silently presenting a fallback as the confirmed frame. Authored timeline scripts defer until fonts settle; preview confirmation additionally requires successful loading of referenced faces, and capture readiness waits for that same font promise. A failed load retains the last confirmed preview and blocks native capture. Web imports fonts through the existing receipt chain and exposes imported faces in the text property selector; SDK font-family edits/clear preserve untouched styles and inheritance. Source/history/ZIP retain original font bytes and notices; larger persistent storage and streamed reads remain separate M2 work. Metadata validation, actual browser font loading, native rendering and human typography acceptance remain distinct. The bounded WOFF2 adapter follows the [WOFF2 container specification](https://www.w3.org/TR/WOFF2/).

Daemon resource_import accepts only immutable request/owner/revision/path/name/digest/byte metadata and optional uploadId. It first confirms the workspace receipt; without a committed receipt/uploadId it returns project:null after checking current ownership/revision/path. resource_upload reserves one of two temporary 16 MiB slots and issues a random business URL for raw application/octet-stream bytes outside JSON/MCP. Exact lengths/digests are checked incrementally into one bounded buffer before adoption; workspace validates the format and atomically commits bytes, manifest, history and receipt. No persistent upload journal or OS allocation is introduced. resource_release/expiry revoke future access while active transfers retain capacity until actual drain. Quiesce aborts and drains reversible byte streams before workspace retirement. A cold restart loses uncommitted staging, while original committed intents replay before any expired ticket/byte lookup and never rewind later edits. Web retains its selected File and original command identity across unknown outcomes. Base64 resource_import inputs are rejected; resource_read issues a temporary read-only binary link rather than embedding data. Uploads and downloads share the same two-slot staging budget; accepted readers hold their slot until drain. HTTP JSON and stock MCP SDK control limits remain unchanged. The revision aggregate stays 64 MiB. This bound is an incremental transfer qualification, not the reference product's 500 MB file/storage parity.

The finite import contract accepts non-interlaced PNG up to 4096×4096 with checked decoding/CRC, and PCM16 RIFF/WAV at 8–96kHz with one/two channels. Each resource is at most 16 MiB; a revision has at most 64 resources / 64 MiB, independently of its text bounds. Daemon serves exact MIME/bytes and bounded single-range byte requests from captured view revisions; close revokes that view. Pure composition assembly resolves nested media through this finite manifest, rejects missing/nonlocal media candidates and retains the last confirmed frame. Web imports/lists/removes resources and inserts image/audio elements through the native SDK and the existing context/save chain. Unknown committed responses retry the same receipt; a transformed insertion is not regenerated after persistence failure. Independent fixed-rate audio supports source in-points, authored rate in 0.1..10, volume in 0..1 and mute. Source-window, duration and rate edits validate atomically: in-point + duration × rate must not exceed verified source length. Remaining-source trim is divided by the rate; rate changes preserve clip start/duration and are distinct from preview transport speed; a source slip preserves clip start/duration, and only touched attributes are written. Preview assembly checks authored source-length hints and media type against verified immutable resource facts. Ramped rate, automation, effects, fades, alternate clock attributes, loop/autoplay and SDK-detected script-driven audio remain read-only; broader codecs need their own contracts. The sandbox keeps an opaque origin and unchanged resource CSP; autoplay permission allows explicit native playback without granting same-origin access. Technical decoding/playback evidence is separate from listening/creative acceptance.

Media links are source-editing metadata, not runtime resource factories or native playback actors. The same opaque link ID is isolated by its owning file and nearest composition, preserving reusable source definitions and repeated mounts. Aligned static PNG/WAV groups can be created, extended and unlinked. All members share numeric start/duration; audio members share numeric source in-point/rate. Movement, right trim and audio source-clock edits validate every member before one SDK batch, source save and history transition. The shortest remaining audio window bounds group trim. Gain/mute and visual appearance remain individual. Deleting a valid group removes all members but preserves resource manifests/bytes and remains undoable. Unlink removes the complete local group's markers and preserves sync-origin metadata. Invalid, drifted, nested, unsupported or SDK-detected dynamic groups remain read-only; unlink is the explicit repair path. Retry retains applied source and the workspace receipt rather than generating a second link. Static analysis follows the pinned SDK's recognized animation/selector forms and does not prove arbitrary author-script side effects. Private source-edit helpers live in `packages/motion/src/editing`; this adds no host resource authority.

External-file hosts appear as parent-file timeline windows. Motion derives their local host identity, child source and numeric source-length limit from the graph. `/motion/host` changes only the declaring parent file through the native SDK; moving and right-edge trimming do not alter child source, child keyframes or playback rate. Windows must remain positive and inside the declared parent and child bounds. Editing a host in a shared parent definition updates all mounts of that definition. Dynamic selectors, linked timing and animations targeting the host remain read-only until their effects have an explicit verified contract. Root metadata, source in-points, slip, stretching and ripple are not part of this operation. Uncommitted raw-source drafts never activate a new preview topology or clock; controls resume from a confirmed snapshot after save or discard.

Preview documents are opaque sandbox frames restricted to their own snapshot resources. Product Web defines no inline styles or telemetry; native content is a separate closed resource contract. Product engine children disable upstream telemetry. Source editing, preview readiness, model execution, rendering, installation and user visual/audio acceptance have independent evidence boundaries.

## Persistent export jobs and fixed-revision execution

`packages/render` owns the export intent journal, serial queue and native execution. Workspace captures confirmed source and immutable PNG/WAV/font bytes once; `project_snapshot` reopens an explicitly owned historical revision without moving current content or history. Execution materializes a bounded, read-only projection under a sidecar staging grant. Expected dimensions/duration/audio come from that fixed source, and frame rate is explicit. The initial contract is H.264/yuv420p MP4, even dimensions up to 4096, at most 600 seconds / 36000 frames, and optional native AAC mixing selected from authored audio. It does not accept a result-derived expectation.

The composer supplies a finite native-tool manifest and loaders; the current default is explicitly qualified for macOS arm64. Blob verifies and materializes the resources; the executor starts a stamped worker and attaches actual worker Uses before opening its execution gate. Chromium, FFmpeg and FFprobe remain descendants of that worker. Static snapshot service ports, staging, browser profiles and temporary/cache paths belong to the same sidecar factory. The pinned native player supplies renderSeek through Motion's capture adapter; no second animation clock or producer HTTP server is introduced. This first adapter covers the native GSAP/PNG/WAV/font contract, not arbitrary timer-driven or remote content.

Explicit native preparation belongs to that same hosted renderer and Blob library, never an installation cache. Private operator methods start a bounded background attempt immediately and read its three-component progress; the composer may await preparation outside business/factory lanes. Each component holds a real renderer Use while verifying materialization, declared executable containment and permissions. All components settle independently, and explicit retry/reopen reuses verified Blob content while retrying failures. Completed status describes that attempt, not permanent cache availability or an execution probe: export still acquires actual worker Uses, and Blob retains its normal GC policy. Preparation starts no tool subprocess. The standalone preparation-only mode hosts the same renderer/Blob owner without Web, Daemon, export-queue construction or export-journal initialization. It denies export controls and cannot resume queued user jobs. The npm entry attaches to an existing full runtime or starts this minimal managed composition and stops only the exact Manager witness it received; it never infers stop ownership from an earlier status probe. Ordinary operator signals abort polling and drain that owned witness even if received during bootstrap; an attached full runtime remains independently owned. Quiesce aborts and drains preparation alongside export execution before library/resource retirement; unresolved cleanup preserves protection and prevents another preparation attempt. No native preparation methods enter the public product HTTP/MCP contract.

Success requires real capture/encoding, input-matching codec/dimensions/fps/duration/audio, full decode with exact frame count, first/middle/last decoded seeks and an output digest. The manager then proves worker-tree retirement before releasing Uses and moving the verified film into persistent export data. Cancellation drains the actual tree. Uncertain retirement preserves its resource protection and staging evidence. Blob GC can reclaim tool resources after Uses drain; it never collects exported films or workspace history.

Standalone composes a hosted `renderer` owner and independent Daemon; Codex reuses that composition. The composer injects the renderer's granted root and delegated business Peer connection privately into Daemon. No root control capability, grant path or process identity enters public job responses or Web bootstrap. Daemon validates artifact ownership, freezes the explicitly selected historical revision, and atomically stages a content-addressed read-only projection in the renderer grant. This is execution input, never another editable project store. Only projection digest/size and intent metadata cross the bounded control wire. Failure diagnostics stay in the private journal; public jobs use bounded lifecycle messages without filesystem paths.

The renderer stores `exports.sqlite` format 1 under its persistent Context grant. Workspace remains format 3 and owns all editable source/media/history. Creation and controls atomically journal request identity, input fingerprint and original receipt. A repeated request confirms the same intent even after a lost response or later project edits. Jobs have explicit attempts, optimistic control versions and queued/preparing/capturing/encoding/verifying/cancelling/terminal states. At most 32 active/queued jobs are accepted; owner-scoped cursor pages contain at most 16 entries. HTTP completion and Web panel disposal do not cancel accepted work; intent is independent of the request transport. Detaching a development MCP client leaves its separately owned runtime running. A self-hosted Codex stdio EOF drains its owned carrier instead: active work becomes interrupted and queued intent persists for restart. Serial execution reuses the fixed `renderpreview` source identity rather than leaving one resource root per job.

Normal carrier shutdown stops new calls, aborts and drains active execution, marks it interrupted, and retains queued intent for restart. Retry of failed/cancelled/interrupted work creates a new attempt against the original frozen revision. Startup reconciles nonterminal jobs with sidecar ownership and committed film receipts. Unknown or still-owned work enters `recovering` and blocks replacement; neither elapsed time nor a PID probe proves retirement. Explicit dead-owner recovery precedes restart after manager interruption. The ready-stage committed-process-witness recovery path is qualified; interruption before process-witness publication remains a separate unqualified startup window and fails closed.

Sidecar's owner-only `Context.cleanup` lets already accepted controllers finish resource release during quiesce. It cannot create/attach new resources after manager closing, cannot run from business callbacks and expires on owner retirement. Blob treats a stopping owner as live until actual drain, retaining Uses on uncertainty. Business handlers only journal or signal work; they do not perform lifecycle operations in request lanes.

Daemon adapts the same create/list/read/cancel/retry/download schemas to authenticated HTTP and MCP. Web saves before submission, retains request identity across unknown receipts and polls bounded pages. Completed downloads issue at most 128 short-lived, read-only tickets with a ten-minute lifetime, verify the exact regular film file's digest/size before streaming, and return MCP `resource_link` metadata rather than embedding a movie or exposing a filesystem path. Tickets expire with the Daemon process; completed jobs and films persist. Deleting exports needs a separate product lifecycle; blob GC never authorizes it.

Native Web export and a Codex closure relocated outside the repository have local macOS arm64 execution evidence. The build retains supplied dependency notices and pins the actual engine provenance version without a runtime package lookup. This is not a published toolchain feed, target-platform installation or asset redistribution/license qualification. Linux/Windows native execution and all startup/power-loss windows need their own evidence; skipped seeded-native tests do not qualify them.

## Development control plane

Dev owns repository configuration, managed builds/watchers and dynamic carrier adapters. CLI parses arguments; adapters are `carriers/*/src/dev.ts`. They register into the injected sidecar manager/factory and never own another authority. Build wrappers, pnpm and compiler descendants belong to a sidecar process tree. Build receipts describe results rather than serving as process inventories.

Sidecar validation runs OS-resource test files serially. Each file creates real managers, process trees, sockets and durable ledgers; unrelated fixtures must not compete against the finite runtime deadlines being verified. Tests still exercise concurrent sessions/controllers and competing lifecycle operations explicitly inside each file. This scheduling policy changes no runtime deadlines, recovery rules or assertions.

Sidecar derives manager roots from base domain/channel/namespace and observes actual control liveness. `stopManager` validates the exact witness/arg stamp and requests drain; timeout preserves authority. Explicit null environment values remove inherited options such as `ELECTRON_RUN_AS_NODE` at the shared launch boundary.

Rebuild and activation are separate: a watcher marks restart required, then explicit restart replaces the development composition. An attached Codex client's EOF closes that transport without stopping the development manager. Production Codex owns and drains its own composition.

Port grants own listeners and both ends of forwarded connections. Owners stop accepting and drain real work before releasing grants; release closes remaining transports and confirms retirement without waiting for browsers to disconnect. Normal FIN preserves buffered response data; abnormal disconnect propagates. Manager quiesce publishes stopping for hosted services while preserving factory-lane drain ordering.

## Native-content business transfer

Daemon owns archive_export/upload/import/release schemas shared by HTTP, MCP and Web. Export freezes an explicitly owned historical revision, including exact persistent PNG/WAV/font bytes, into a deterministic ZIP. MCP returns an application/zip resource link with digest/size/filename, never binary data or a host path. Upload declares exact raw digest/size and reserves a business URL; application/zip bytes bypass the32MiB JSON/control limit. No arbitrary URL fetch or host-path operation is introduced.

Two in-memory tickets bound aggregate staging capacity. Each accepts at most72MiB, expires after ten minutes and permits one active transfer; a transfer has a one-minute deadline. Request identities retain the same ticket/intent within that temporary lifetime. Release/expiry revoke future access, but active streams retain their slot until actual drain. Quiesce rejects new work and aborts reversible byte streams before workspace close and sidecar resource retirement. Tickets and uncommitted staging disappear on restart; there is no filesystem, journal, watcher, listener or Blob authority in this adapter.

Import first confirms the workspace immutable-source receipt using the original request/session/title/raw digest. With no receipt and no uploadId it returns artifact:null. A verified upload then creates complete independent source/media/history through one workspace transaction without changing selection. Replay precedes upload lookup, so expiry, later edits or a cold restart do not duplicate or rewind committed content. A missing uncommitted upload requires restaging identical bytes. Web saves before export/import and retains unknown import intent and the selected File for explicit retry; it opens a created artifact through the existing selection transaction. Byte integrity/creation are separate from complete template dependency closure, cover/film/creative acceptance and relocated native execution.
